RebateHarbor - Multi-page Application Portal
October 21, 2026

WHAT IS BUILT
A connected online application journey, not just a help-request landing page:
/apply - application introduction and account sign-in
/apply/[id]/details - applicant, property and utility details
/apply/[id]/upgrade - equipment, project stage and rebate program details
/apply/[id]/documents - private PDF, PNG and JPEG uploads
/apply/[id]/review - final review, consent, submission and receipt
/my-applications - saved drafts, submitted applications and status updates
/team/applications - authorized reviewer queue, attached documents and customer-visible status notes

The existing rebate finder, state resources, estimates, help pages and redesigned homepage remain available. Navigation and legacy /applications links now lead to Apply online.

HOW IT WORKS
Visitors sign in using the existing Sites ChatGPT sign-in flow. They can save and resume an application. Project data is saved in D1, with application-specific documents in private R2 storage. Upload limits: 10 MB per document, 24 documents per application. Accepted formats: PDF, PNG, JPEG, with basic file-signature checks. Files are downloaded as attachments and are not automatically scanned, parsed or verified.

The applicant reviews and consents before sending the application to RebateHarbor. Submission requires contact/property/project details and at least one supporting file. The server saves a receipt and locks editing during review. The authorized reviewer can add notes, request information, or record progress. A request for more information reopens editing; the applicant can make changes and resubmit. Utility submission and approval statuses require a recorded reference and a customer-visible note. Status updates are team-recorded, not a live utility feed.

PRIVACY AND ACCESS
Public visitors cannot list applications or download their files. Every applicant API checks sign-in and application ownership. Team access is checked server-side against the runtime REBATE_TEAM_EMAIL setting. Team routes exclude private, unsubmitted drafts. Cross-origin mutations are rejected. Concurrent saves use a version check to avoid silently overwriting another window. File uploads check application status again when attaching the object.

WHAT SUBMISSION MEANS
The online form submits a full application and documents TO REBATEHARBOR for review. It does not submit an official utility application, sign for the applicant, reserve funding or promise a rebate. Official utility submission still needs the administrator's supported process and any required customer authorization. There is no payment collection or automatic email service.
